# Database Schema

> **Status:** Design phase — no migrations exist yet. This document is the authoritative data model; [`../packages/database/`](../packages/database/) holds the Drizzle schema, migrations and seeds that implement it.
> **Engine:** Neon PostgreSQL (serverless, pooled runtime connection).
> **Tooling:** Drizzle ORM 0.45.4 + `drizzle-kit`; Better Auth tables are generated by the Better Auth CLI, not hand-written.

---

## 1. Principles

1. **Ownership first.** Every user-owned table carries `user_id`. No user-owned table is queryable without that predicate.
2. **Immutability where memory matters.** The user's original words (`entries.original_text`) and every transcript are write-once.
3. **Append-only AI.** `ai_generations` accumulates versions; approval is a flag, not an overwrite.
4. **Multiple entries per day** is a hard requirement — therefore **no** unique constraint on `(user_id, entry_date)`.
5. **Dates are business dates.** `entry_date` is a `DATE`, not a timestamp; timezone logic lives in application code using `profiles.timezone`.
6. **Soft delete for entries** so an accidental delete is recoverable.
7. **Cascade from the user.** Deleting an account removes all owned rows; deleting an entry removes its children.

## 2. Entity Relationship Overview

```text
user ──1:1── profiles
 │
 ├──1:N── entries ──1:N── answers ──N:1── questions
 │           ├──1:N── moods
 │           ├──1:N── ai_generations
 │           └──1:N── attachments        (PLUS)

 ├──1:N── transcriptions ──0:1── entries (entry_id, nullable)

 ├──1:1── reminders
 ├──1:N── journal_chats ──1:N── journal_chat_messages   (PLUS)
 └──1:N── reflections                                   (PLUS)
```

## 3. Tables

### 3.1 Better Auth tables (generated, never hand-written)

Generated with `npx auth@latest generate --adapter drizzle --dialect postgresql` into `packages/database/schema/`, then migrated normally. Regenerating after a Better Auth upgrade must produce no diff.

| Table | Key columns | Notes |
|---|---|---|
| `user` | `id` (PK), `name`, `email` (UNIQUE), `email_verified`, `image`, `created_at`, `updated_at` | Created/migrated by Better Auth CLI — do not hand-edit |
| `session` | `id` (PK), `user_id` FK, `token`, `expires_at`, `ip_address`, `user_agent` | Server-side invalidation on logout |
| `account` | `id` (PK), `user_id` FK, `provider_id`, `account_id`, `password` | Password hashes only — never plaintext |
| `verification` | `id` (PK), `identifier`, `value`, `expires_at` | Email verification / reset tokens |

**Rule:** no custom `users` table. Profile data lives in `profiles` keyed by `user.id`.

### 3.2 `profiles`

| Column | Type | Constraints |
|---|---|---|
| `user_id` | `TEXT` | PK, FK → `user.id` ON DELETE CASCADE |
| `display_name` | `TEXT` | NOT NULL |
| `avatar_url` | `TEXT` | NULL |

### 3.3 `entries`

| Column | Type | Constraints |
|---|---|---|
| `id` | `UUID` | PK, default gen_random_uuid() |
| `user_id` | `TEXT` | NOT NULL, FK → `user.id` ON DELETE CASCADE |
| `entry_date` | `DATE` | NOT NULL |
| `title` | `TEXT` | NULL, ≤ 200 chars |
| `original_text` | `TEXT` | NOT NULL default `''`, **immutable after first save** |
| `final_text` | `TEXT` | NOT NULL default `''` |
| `language` | `TEXT` | NULL, BCP-47 style (`en`, `ur`, `hi`) |
| `status` | `TEXT` | NOT NULL, CHECK IN (`draft`,`complete`), default `draft` |
| `ai_generation_id` | `UUID` | NULL, FK → `ai_generations.id` ON DELETE SET NULL |
| `word_count` | `INTEGER` | NOT NULL default 0 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL default now |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL default now |
| `deleted_at` | `TIMESTAMPTZ` | NULL (soft delete) |

**Constraints**
- `CHECK (status <> 'complete' OR length(btrim(final_text)) > 0)` — cannot complete an empty entry.
- `CHECK (length(final_text) <= 100000)` — server-side length ceiling.
- **No** unique `(user_id, entry_date)` — multiple entries per day are valid.

**Indexes**
- `idx_entries_user_date` on `(user_id, entry_date DESC)` — calendar + history.
- `idx_entries_user_active` on `(user_id, deleted_at)` — list filtering.
- `idx_entries_search` GIN on `to_tsvector('simple', coalesce(title,'') || ' ' || final_text)` — full-text search.
- `idx_entries_ai_gen` on `(ai_generation_id)`.

### 3.4 `questions`

| Column | Type | Constraints |
|---|---|---|
| `id` | `UUID` | PK |
| `user_id` | `TEXT` | NULL — NULL means a system question |
| `prompt` | `TEXT` | NOT NULL, ≤ 500 chars |
| `sort_order` | `INTEGER` | NOT NULL default 0 |
| `is_active` | `BOOLEAN` | NOT NULL default true |
| `is_system` | `BOOLEAN` | NOT NULL default false |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | NOT NULL |

**Rule:** `CHECK (is_system = (user_id IS NULL))` — a system question has no owner; a custom question must have one.
Index: `idx_questions_owner` on `(user_id, sort_order)`.

Seeded system questions (12, fixed order): How was your day · Best thing that happened · What new thing you learned · Did you accomplish your goals · Challenges faced · What made you happy · Anything disappointing · Important work done · Time with someone special · What you are grateful for · What you could do better · Plans for tomorrow.

### 3.5 `answers`

| Column | Type | Constraints |
|---|---|---|
| `id` | `UUID` | PK |
| `entry_id` | `UUID` | NOT NULL, FK → `entries.id` ON DELETE CASCADE |
| `question_id` | `UUID` | NOT NULL, FK → `questions.id` ON DELETE CASCADE |
| `answer_text` | `TEXT` | NOT NULL default `''` |
| `is_skipped` | `BOOLEAN` | NOT NULL default false |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | NOT NULL |

- UNIQUE `(entry_id, question_id)` — one answer per question per entry.
- `CHECK (is_skipped = false OR answer_text = '')` — skipping and answering are mutually exclusive.
- Index: `idx_answers_entry` on `(entry_id)`.

*Note:* `user_id` is reachable via `entries`, but every query still joins through the owned entry — ownership is never inferred from a parent ID supplied by the client.

### 3.6 `moods`

| Column | Type | Constraints |
|---|---|---|
| `id` | `UUID` | PK |
| `user_id` | `TEXT` | NOT NULL, FK → `user.id` ON DELETE CASCADE |
| `entry_id` | `UUID` | NULL, FK → `entries.id` ON DELETE CASCADE |
| `record_date` | `DATE` | NOT NULL |
| `mood` | `TEXT` | NOT NULL, CHECK IN the 10 allowed values |
| `intensity` | `SMALLINT` | NULL, CHECK 1..5 |
| `note` | `TEXT` | NULL, ≤ 500 chars |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | NOT NULL |

Allowed `mood` values: `happy`, `excited`, `peaceful`, `motivated`, `normal`, `tired`, `stressed`, `sad`, `frustrated`, `anxious`.

- UNIQUE `(entry_id)` where `entry_id IS NOT NULL` — one mood per entry.
- Indexes: `idx_moods_user_date` on `(user_id, record_date)`; `idx_moods_value` on `(user_id, mood)` for distribution.

### 3.10 `reminders`

| Column | Type | Constraints |
|---|---|---|
| `user_id` | `TEXT` | PK, FK → `user.id` ON DELETE CASCADE |
| `enabled` | `BOOLEAN` | NOT NULL default false |
| `time_local` | `TIME` | NOT NULL default `'21:00'` |

### 3.11 PLUS tables (created with the core schema, unused until Phase 13)

`attachments` — `id`, `user_id`, `entry_id`, `kind` (`image`|`document`|`audio`), `storage_key`, `mime`, `size_bytes`, `caption`, `created_at`. Signed URLs only; no public bucket path stored.

`journal_chats` — `id`, `user_id`, `title`, `created_at`, `updated_at`.
`journal_chat_messages` — `id`, `chat_id`, `role` (`user`|`assistant`), `content`, `cited_entry_ids` (`UUID[]`), `created_at`.

`reflections` — `id`, `user_id`, `period_start`, `period_end`, `insights_json` (`JSONB`), `model`, `prompt_version`, `created_at`.

## 4. Cascading Behaviour

| Parent deleted | Effect |
|---|---|
| `user` | Cascades to `profiles`, `entries`, `moods`, `transcriptions`, `ai_generations`, `preferences`, `reminders`, `attachments`, `journal_chats`, `reflections`, and Better Auth `session`/`account` rows |
| `entry` | Cascades to `answers`, `ai_generations`; `transcriptions.entry_id` → NULL (helps preserve the memory); `moods` cascade |
| `question` (custom) | Cascades to its `answers` |
| `ai_generation` | `entries.ai_generation_id` → NULL |

Design intent: deleting an entry must never destroy the raw transcript the user spoke.

## 5. Migration & Seed Strategy

- Every change ships as a versioned migration in [`../packages/database/migrations/`](../packages/database/migrations/) — generated by `drizzle-kit`, reviewed before commit, with a documented rollback.
- Migrations run against the **direct** Neon URL; the app runs on the **pooled** URL.
- Seeds in [`../packages/database/seeds/`](../packages/database/seeds/) are idempotent and guarded by `NODE_ENV !== 'production'`.
- Multi-table writes use the transaction-capable driver path (see `TECH_STACK.md` §6 — the Neon HTTP driver cannot hold a transaction).
- No manual DDL against any shared environment. Ever.
